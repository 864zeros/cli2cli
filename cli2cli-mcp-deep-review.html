1. Executive Summary & Purpose

The Core Thesis: Process vs. API

Most existing multi-agent frameworks orchestrate cloud model API calls (e.g. sending prompts to a hosted endpoint). cli2cli-mcp fundamentally flips the unit of orchestration to actual CLI processes running on local hardware.

By wrapping executions in a real pseudo-terminal (Windows ConPTY via node-pty), agents execute with full access to the local filesystem, local repositories, shell binaries, and authenticated user credentials.

Open-Core Architecture & Ecosystem Role

An open-core, un-opinionated, standalone repository (MIT licensed). It functions as the hardware/process substrate.

Higher-level orchestration (routing output between agents, dispatch state machines, and Telegram/SMS gateways) resides in consumer layers and gateway daemons.

4. Key Subsystem Analysis

Platform & Binary Resolution

Windows installs CLI tools (e.g. claude, gemini) as .cmd or .bat wrappers on the PATH. ConPTY requires resolved executables. resolveCommand() scans directory entries and tests candidates against PATHEXT.

// src/index.ts line 94
function resolveCommand(command: string): string {
  if (command.includes("/") || command.includes("\\")) return command;
  if (!IS_WIN) return command;
  for (const dir of pathDirs) {
    for (const ext of exts) {
      const candidate = join(dir, command + ext);
      if (existsSync(candidate)) return candidate;
    }
  }
}

Credential Protection & Sanitization

Placeholder API keys in global environment files (e.g. ANTHROPIC_API_KEY="your-api-key-here") override valid cached OAuth credentials, causing spawned CLI subagents to crash. scrubEnv() drops placeholder values automatically.

Human-in-the-Loop (HITL) Prompt Detection

When an interactive agent halts for user confirmation, standard pipes hang indefinitely. HITL_PROMPT_PATTERN matches incoming chunks and raises a flag so remote hosts can present an Approve/Reject prompt.

Pattern: /(\(y\/n\)|\[y\/n\]|yes\/no|approve|confirm|proceed\??|overwrite|are you sure|press enter|choose an option|select an option|❯)/i

Sliding-Window Memory Management

To prevent runaway chatty processes or compilation logs from filling host memory, session output buffers are clamped to a sliding window of 200,000 characters (MAX_BUFFER_CHARS).

When read_cli_stream is called, the accumulated buffer is transferred and cleared (destructive drain).

6. Technical Observations & Decision Points

Architectural Considerations Before Starting Work

  • Claude CLI Preset Default: resolvePreset("claude") defaults to ["--print", initialPrompt]. This runs Claude in non-interactive batch mode and terminates. If multi-turn interactive steering is desired, the caller must use cli_type: "custom" or we should add an interactive preset toggle.
  • Raw ANSI Escape Codes: The stream output contains raw VT100/ANSI sequences (colors, cursor positioning). Upstream consumers must strip ANSI themselves (e.g. via regex in downstream client orchestrators), unless we add an optional strip_ansi: boolean parameter to read_cli_stream.
  • Process Tree Termination on Windows: session.process.kill() issues a kill command via node-pty. Deep process trees spawned via cmd.exe may require tree-kill safeguards (e.g. taskkill /F /T) to prevent orphaned processes.
  • In-Memory Session Accumulation: Exited sessions remain in the sessions Map indefinitely until explicitly deleted via terminate_cli_session. A TTL or auto-pruning sweep could be added for long-running servers.
