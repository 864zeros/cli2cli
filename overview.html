What it does

Turns interactive CLIs into tools an AI can drive.

A model's built-in shell tool can run ls — but the moment a program asks a question (Proceed? (y/n), an arrow menu, a wizard, a password), it stalls, because there's nobody at the keyboard to answer.

cli2cli-mcp launches the program inside a real pseudo-terminal (ConPTY on Windows) and exposes five simple tools. Now the assistant can spawn it, read its output, notice it's waiting, write the answer, and repeat — supervising a live, interactive session end-to-end.

It's key-free: this is an MCP server, so the intelligence lives on the host session that connects to it. cli2cli-mcp is just the terminal driver — no API key, no .env, no model calls of its own.

Before: interactive = blocked

  • The AI's shell hangs on any prompt
  • Wizards / menus / logins can't be automated
  • Confirmations need a human at the terminal
  • No way to feed answers to a running CLI

After: spawn → read → write

  • Any interactive CLI runs in a real PTY
  • The assistant reads prompts and types answers
  • Confirmations, menus, logins — all drivable
  • One MCP server any host can register

read_cli_stream also returns an is_waiting_for_input flag — a heuristic that spots confirmation prompts ((y/n), "approve", "overwrite", menu selectors) so the caller knows when a decision is needed rather than polling blindly.

Why a real pseudo-terminal

Interactive CLIs behave differently when they think they're talking to a terminal (colors, cursor control, prompts) versus a pipe. cli2cli-mcp uses node-pty — Windows ConPTY — so programs run exactly as they would for a human, and stdin injection actually reaches them. It also runs on POSIX.

Why key-free is the point

Because it's an MCP server, the LLM is the client — the session that connects to it. cli2cli-mcp never calls a model. It carries no credentials, ships no .env, and adds no per-call cost. It does exactly one job — drive terminals — and stays a clean, generic substrate.

Verified & honest

What's proven

  • Smoke test: real ConPTY round-trip (spawn a shell, drive it, read output, exit 0)
  • Driven live by Claude Code as a registered MCP server
  • Used as the execution substrate under a separate workflow engine
  • Extracted to its own repo; smoke-passes standalone

Be clear-eyed

  • Windows-first (ConPTY); POSIX works but is less exercised
  • The interactive-prompt flag is a regex heuristic — it can miss unusual prompts
  • Output carries raw ANSI/terminal escapes; the caller strips them
  • It's a substrate — it drives CLIs, it doesn't decide what to run

Developer & operator reference

Architecture — one server, one file

MCP host (Claude Code · Cursor · Desktop · a script)
      │  stdio (JSON-RPC / MCP)
      ▼
cli2cli-mcp  src/index.ts  →  dist/index.js      # the whole server, 5 tools
      │  node-pty (Windows ConPTY / POSIX)
      ▼
   any interactive CLI  (claude · gemini · shell · custom)

Runtime deps: @modelcontextprotocol/sdk, node-pty, uuid. Sessions are held in memory with bounded output buffers; env placeholders (e.g. a stray ANTHROPIC_API_KEY=your-api-key-here) are scrubbed before a child is spawned.

The five tools

ToolSignaturePurpose
spawn_cli_session({cli_type, initial_prompt?, working_dir?, command?, args?}) → {session_id}Launch a CLI in a PTY. cli_type: claude · gemini · shell · custom.
read_cli_stream({session_id}) → {output, is_waiting_for_input, is_exited, exit_code}Drain new output; flag an interactive pause or exit.
write_cli_input({session_id, input_text, append_newline?}) → {ok}Feed stdin — confirmations, answers, raw keystrokes.
list_cli_sessions() → {sessions[]}Every live session and its state.
terminate_cli_session({session_id}) → {ok}Kill a session and free its resources.
Presets are de-opinionated. The claude preset defaults to safe (--print, no auto-skip-permissions). Anything opinionated or autonomous is the caller's choice via cli_type:"custom" with explicit command + args — so the substrate stays generic.

Register (MCP config)

"mcpServers": {
  "cli2cli": {
    "command": "node",
    "args": ["C:/dev/cli2cli-mcp/dist/index.js"]
  }
}

Or one-liner: claude mcp add cli2cli -- node .../dist/index.js.

Build & verify

cd C:\dev\cli2cli-mcp
npm install       # node-pty prebuilt
npm run build     # tsc → dist/
node scripts/smoke.mjs   # PTY round-trip

Node ≥ 20. Smoke test needs no external CLI.

Notes & gotchas

ItemDetailHandling
ANSI in outputConPTY emits colors/cursor codes; results carry escape sequences.The caller strips them (the host session, or your wrapper).
Windows binary shimsclaude/gemini are .cmd shims; ConPTY needs the resolved path.Bare names are resolved via PATH/PATHEXT at spawn.
Multi-line via argvA newline in an argv passed through claude.cmd truncates.Feed long/multi-line prompts via stdin or a redirected file, not argv.
Interactive-prompt flagis_waiting_for_input is a regex heuristic.Treat it as a hint; the caller can always read + decide directly.
Placeholder env varsA dummy key in the environment can break a spawned CLI.The server scrubs obvious placeholders before spawning children.
