01 · Ecosystem Topology

The Three Open-Source Pillars

To make the entire stack 100% free, open-source, and immediately usable by any developer, the architecture is cleanly divided into three modular pillars with zero hardcoded personas or proprietary lock-in:

PILLAR 1 · THE SHIP'S BRIDGE

cli2cli-helm

Persistent PTY Daemon & Terminal Multiplexer. Runs helm-daemon in the background so closing your terminal or restarting an IDE never kills active agents. Includes the multi-pane TUI cockpit (Single, Split-2, Grid-4), the c2c JSON CLI, and Helm Link peer discovery.

PILLAR 2 · THE ENGINE ROOM

cli2cli-mcp

Stateless MCP Protocol Adapter. Exposes 6 standard Model Context Protocol tools (spawn, read, write, wait, list, terminate) connected to helm-daemon. Enables any upstream LLM to orchestrate sibling CLI agents with zero polling.

PILLAR 3 · OUTWARD COMMAND CENTER

cli2cli-aoe

Remote HITL Governance & Live Telemetry. Routes BLOCKED confirmation prompts to your phone (Telegram, Slack, Webhook) with inline Approve / Reject buttons, an optional bring-your-own-prompt AI Risk Briefer (summarizer.py), and a live SSE web dashboard.

How the 3 Pillars Connect Over Named Pipe IPC

Unlike v0.1—where PTY processes lived inside a single ephemeral MCP stdio server—helm-daemon is now the persistent single source of truth. Multiple consumers (the local TUI cockpit, upstream MCP hosts, sibling CLI agents, and the outward AOE command center) attach concurrently without stealing bytes from each other.

03 · Internal Mechanics (Embedded SVG)

The 4-State Engine & Non-Destructive Cursor Ring Buffer

Two core innovations power helm-daemon: (1) a dual-signal state machine that combines Herdr's OSC 7501 escape protocol with our zero-config ANSI regex heuristic, and (2) an offset-indexed ring buffer so multiple tools can read the same terminal stream without race conditions.

06 · Quick Reference

Using c2c / cli2cli-helm, MCP Tools, and AOE

1. Scriptable CLI & Multiplexer (c2c)

# Launch the 8-slot interactive TUI cockpit
c2c
# Inside TUI: [1-8] Slot · [v] Single/Split2/Grid4 · [y/n] Approve/Reject · [q] Detach

# Or drive helm-daemon from scripts / sibling agents (JSON output):
c2c ping
c2c spawn claude "Refactor auth.ts and run tests" --slot 1
c2c wait 1 --until blocked,idle,exited --timeout 60000
c2c send 1 "y"
c2c read 1 --tail 2000
c2c list
c2c kill 1

# Emit OSC 7501 status directly from inside any child script:
c2c status blocked

2. Outward Command Center Config (cli2cli-aoe)

# .env configuration in cli2cli-aoe (100% vendor-neutral)
TELEGRAM_BOT_TOKEN=your_bot_token
ALLOWED_TELEGRAM_USER_IDS=123456789

# Summarizer Mode:
#   "raw" = $0 LLM cost, sends clean terminal tail + Approve/Reject buttons
#   "ai"  = summarizes action & risk via pluggable prompt before alerting
AOE_SUMMARIZER_MODE=raw

# Optional: Bring your own custom persona prompt file (e.g. custom_briefer.md)
# Defaults to a neutral DevOps & Security Risk Briefer if left blank.
